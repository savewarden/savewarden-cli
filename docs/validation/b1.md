## Conditions techniques bloquantes du plan

| Condition | Réponse | Preuve |
| --- | --- | --- |
| 1. Confinement ≠ non-suivi | `os.Root` n'est jamais seul. Sous Windows, chaque dossier traversé est ouvert avec `FILE_FLAG_OPEN_REPARSE_POINT`, vérifié sur son handle et gardé ouvert sans `FILE_SHARE_DELETE` ; chaque fichier est ouvert de même et refusé si le handle montre un point d'analyse, un dossier ou un placeholder | Test d'un lien symbolique relatif qu'`os.Root` suit, refusé par la portée ; jonction dans la portée, en ancre, substituée après `Lstat` ; renommage d'un dossier épinglé refusé |
| 2. Port en portée ancrée | `FileSystem.OpenScope` puis `Scope` à noms relatifs ; identité contrôlée sur le handle ouvert ; échec fermé | `internal/features/inspect/ports.go` ; tests de remplacement entre `Lstat` et ouverture |
| 3. Garde AST non surestimé | Garde statique documenté comme tel ; tests dynamiques ajoutés | Binaire réel lancé deux fois, environnement isolé, écriture refusée par ACL sous Windows et `chmod` sous Unix, empreinte complète identique |
| 4. Anomalies spécifiées | Source requise absente : code 2 ; facultative absente seule : information, code 0 ; illisible ou point d'analyse : code 2 ; manifeste invalide ou interruption : code 1 sans rapport ; rapport impossible à écrire en entier : code 1, préfixe tronqué possible sur stdout | ADR 0003 amendé ; tests `cli`, `app` et service, dont une écriture qui échoue après 40 octets |
| 5. Portabilité honnête | Grammaire Windows écrite sans `filepath`, verdict identique partout, confrontée à `filepath` sous Windows ; bout en bout Windows seulement ; refus explicite des volumes Windows sous Unix | `winpath_windows_test.go` ; `inspect_windows_test.go` ; `inspect_unix_test.go` |
| 6. Intégrité au mieux | Identité, taille et date contrôlées avant, à l'ouverture et après lecture ; limite « pas un instantané atomique » documentée ; aucune sortie partielle en cas d'annulation | Tests de changements concurrents injectés ; `docs/commands/inspect.md` |

## Écarts au plan

- Le port renvoie `fs.File` au lieu d'une interface `File` propre : tous les
  types du port viennent de la bibliothèque standard, et `app` fait le pont,
  sans import de la feature par l'adaptateur.
- Fichiers de l'adaptateur nommés `scope_windows.go`, `scope_unix.go` et
  `scope_other.go` ; une implémentation Unix, non supportée, sert aux tests
  du contrat.
- Tous les champs du manifeste sont obligatoires, y compris `base` et
  `required`, pour éviter toute valeur implicite.
- Un chevauchement de sources découvert à l'exécution, par nom court 8.3,
  est une erreur fatale, code 1, comme un manifeste invalide.
- `case-collision` est classé bloquant ; le plan ne le précisait pas.
- Fichiers OneDrive et dédupliqués refusés, car ce sont des points
  d'analyse ; ouvertures avec `FILE_FLAG_OPEN_NO_RECALL`.
- Exclusions `gosec` : G304 annoté sur deux appels de production, G204,
  G304 et G122 exclus dans les tests seulement, G302 annoté dans un test.
- Le plan prévoyait « rien sur stdout » pour tout code 1. Le contrat réel,
  fixé par ADR 0003 amendé, admet un préfixe tronqué quand l'écriture du
  rapport échoue. Le texte du plan revu n'est pas modifié.
- Commits supplémentaires : le plan versionné, le durcissement des tests en
  CI et les deux amendements de revue.

## Risques résiduels

- Inventaire non atomique : une modification préservant taille, date et
  identité passe inaperçue.
- Lecteurs `subst` non détectés comme redirection.
- Le garde statique ne couvre que les API connues.
- Sous Unix, course échange puis restauration d'un parent entre deux
  contrôles ; sans effet produit, `inspect` y refusant les chemins Windows.
- Mainteneur unique : revue humaine et Human GO restent le contrôle final.
